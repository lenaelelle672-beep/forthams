# B 端工作台预览路由设计

## 背景

用户希望先验证一套接近参考图的 B 端工作台视觉方案。重点不是立即替换现有前端，而是在当前项目中先显示一套新的桌面工作台效果，观察视觉、路由、菜单交互和工程落地可行性。

参考方向：
- 蓝白浅色工作台背景，顶部有品牌感标题和深色导航条。
- 左侧为图标式菜单，当前项高亮，菜单交互比传统长侧栏更轻。
- 首页由 KPI 卡片、环形评分、风险统计、列表排行、趋势图等信息块组成。
- 整体密度偏 B 端运营驾驶舱，但仍保持清爽、可扫描。

## 目标

第一版新增一个桌面端预览路由，建议路径为 `/workspace-preview`。

这个路由用于验证：
- 参考图风格是否适合 forthAMS。
- 新菜单交互是否比现有 AppLayout 更符合用户偏好。
- 在当前 Vite + React + React Router 工程内能否稳定运行。
- 后续是否值得把这套风格沉淀为正式 Dashboard 或新版桌面布局。

## 非目标

第一版不做以下事情：
- 不替换现有 `/dashboard`。
- 不复制整套项目。
- 不修改移动端 `frontend/src/pages/mobile/**` 和移动端路由。
- 不改现有业务列表、详情、表单页面。
- 不重构全局 AppLayout。
- 不接入复杂权限配置或后端新接口。

## 推荐方案

在当前项目中新增独立页面与独立路由：

- 新增页面目录：`frontend/src/pages/workspace-preview/`
- 新增页面组件：`WorkspacePreviewPage.tsx`
- 如样式较多，新增同目录样式文件或局部组件文件。
- 在 `frontend/src/router/index.tsx` 新增 lazy import 和受保护子路由。
- 路由放在现有 `AppLayout` 内或作为独立全屏路由，需要实现时根据视觉效果决定：
  - 若要最大程度贴近参考图，优先使用独立全屏路由，不套现有 AppLayout。
  - 若要复用现有登录保护，则仍放在 `ProtectedRoute` 下。

推荐第一版使用独立全屏受保护路由：

```tsx
{ path: 'workspace-preview', element: S(WorkspacePreviewPage) }
```

## 页面结构

第一版页面包含五个区域：

1. 品牌与顶部栏
   - 深色横向顶部区域。
   - 展示系统品牌、当前位置、搜索/全屏/文字/用户等图标入口。
   - 图标可先做静态按钮，不绑定真实业务动作。

2. 左侧图标菜单
   - 深色品牌区 + 浅色竖向菜单。
   - 菜单项使用图标加短文本。
   - 当前项使用蓝色渐变高亮。
   - 支持 hover、active、点击切换当前菜单状态。
   - 第一版点击菜单只切换视觉状态，不跳转业务页面，避免扩大路由影响。

3. KPI 卡片行
   - 节点设备总数、防火墙、路由/交换、负载均衡等示例指标。
   - 卡片使用白底、轻阴影、蓝色进度条和小型装饰图形。

4. 核心指标区
   - 攻击面综合安全指数环形评分。
   - 策略风险统计环形图。
   - 右侧主机攻击面风险 TOP10、策略规则风险 TOP10。

5. 底部数据分析区
   - 参考图下半部分做一排或两排分析面板。
   - 包含中心环形态势图、排行列表、折线/柱状趋势。
   - 第一版可以使用 mock 数据，重点验证视觉密度与布局。

## 数据流

第一版优先使用页面内 mock 数据：
- 减少对后端接口的依赖。
- 避免影响现有 dashboard 查询。
- 便于快速贴近截图中的数据形态。

如果后续视觉通过，再逐步替换为真实数据：
- KPI 可映射到资产、设备、风险、工单等现有统计接口。
- TOP 列表可接入资产风险、审计、维保或盘点相关接口。
- 图表可复用现有 `recharts` 或 `echarts` 依赖。

## 交互

第一版必须实现：
- 左侧菜单 hover 状态。
- 左侧菜单 active 高亮。
- 顶部图标按钮 hover 状态。
- KPI/面板 hover 轻微提升或阴影变化。
- 页面在常见桌面宽度下无横向溢出。

第一版可以暂缓：
- 菜单真实跳转。
- 用户菜单下拉。
- 全屏按钮真实调用。
- 搜索弹窗。
- 数据刷新。

## 响应式

范围限定为桌面端预览：
- 主要适配 1440px、1366px、1280px。
- 宽屏可拉开面板间距。
- 窄于 1024px 时允许堆叠或横向压缩，但不作为第一验收重点。
- 移动端不纳入本次范围。

## 风险与边界

主要风险：
- 修改 `frontend/src/router/index.tsx` 会触及全局路由，需要影响分析后再编辑。
- 截图风格偏驾驶舱，若全站套用，可能与现有业务表格页密度和交互不完全一致。
- 如果一开始复制项目，后续会产生双工程维护和合并成本。

控制方式：
- 只新增独立路由和独立页面。
- 不改现有 `/dashboard`。
- 不改 `AppLayout`。
- 不改移动端。
- 实现前对路由相关符号运行 GitNexus impact analysis。

## 验收标准

第一版完成后应满足：
- 登录后可访问 `/workspace-preview`。
- 页面整体观感接近参考图：蓝白背景、深色顶栏/品牌区、图标菜单、密集卡片和图表工作台。
- 左侧菜单可 hover、点击并保持 active 状态。
- 页面不影响 `/dashboard`、`/bigscreen`、移动端 `/m` 路由。
- `npm run build` 或项目约定的前端检查通过。
- 使用浏览器预览截图确认主要区域完整显示。

## 后续决策

预览通过后有三条后续路径：
- 保留为独立驾驶舱入口。
- 将 `/dashboard` 替换为新版工作台。
- 抽象为新版桌面布局主题，再逐页迁移现有业务模块。
