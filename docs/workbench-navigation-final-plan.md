# 固定资产 Workbench 导航与落地方案（最终固化版）

> 日期：2026-06-17  
> 范围：`/fixed-assets/workbench` 信息架构、顶部导航、左侧导航、系统配置、CIP 在建工程、通用集成、表单/待办/交接能力。  
> 参考：字段级 PRD、Dashboard Integration Plan、CIP 集成方案、现有 forthAMS 模块能力。

## 1. 最终结论

Workbench 不按旧导航照搬，也不把报表 KPI 作为主结构。最终采用：

- 顶部导航：4 个业务视角 + 1 个系统配置入口。
- 业务左侧导航：表格主导，承接具体业务模块和明细操作。
- 系统配置左侧导航：进入后台管理态，承接流程、权限、基础资料、集成、通知、系统参数。
- 常用报表：放在业务态 `工作概览 > 常用报表`，不放顶部导航。
- 大屏态势：放在业务态 `工作概览 > 资产态势大屏`。
- 非生产物料采购核销、到货确认、SSE 维保：本轮不进入 Workbench 导航。
- 移动端：不做独立移动 App，仅提供 H5 页面挂载到钉钉；表单采用一套定义，桌面和 H5 分别配置布局。

## 2. 导航原则

### 2.1 顶部导航原则

顶部前四个导航是快速业务视角，不和左侧导航绑定。它们可以展示摘要、趋势、风险、快捷入口，但不拥有具体业务列表。

具体列表、审批、详情、导出、配置、闭环处理，都从左侧导航进入。

`系统配置` 是唯一例外：点击后切换为后台管理态，左侧导航从业务模块变为系统配置模块。

### 2.2 左侧导航原则

左侧导航只放用户要长期进入、能承载表格和操作闭环的模块。

不放：

- 一次性入口。
- 仅展示 KPI 的页面。
- 与业务闭环无关的装饰型页面。
- 已经可以在模块工具栏内解决的报表。

## 3. 顶部导航定义

```text
资产运营总览
数据监控中心
资产运维中心
风险预警中心
系统配置
```

| 顶部入口 | 类型 | 定义 | 进入后左侧导航 |
|---|---|---|---|
| 资产运营总览 | 业务视角 | 固定资产整体运营视角，展示资产规模、待办、入账、CIP、报表、大屏、风险摘要。 | 不切换，仍使用业务左侧导航 |
| 数据监控中心 | 业务视角 | 外部数据源与同步质量视角，MES 是当前主要数据源，后续可接 ERP/EHR/PO/合同及其他系统。 | 不切换，仍使用业务左侧导航 |
| 资产运维中心 | 业务视角 | 资产运维视角，关注台账、盘点、重点设备、维保、工单和转固协同。 | 不切换，仍使用业务左侧导航 |
| 风险预警中心 | 业务视角 | 跨模块风险视角，聚合告警、审批异常、盘点异常、同步异常和闭环处置。 | 不切换，仍使用业务左侧导航 |
| 系统配置 | 后台管理态 | 系统级配置入口，进入后切换为流程、权限、资料、集成、通知、参数等后台导航。 | 切换为系统配置左侧导航 |

## 6. 表单、H5 与待办字段方案

### 6.1 一套表单定义，两套布局

移动端只做 H5 页面挂在钉钉，不单独建设移动 App，也不维护独立移动端流程。

推荐方案：

- 一套表单字段定义。
- 桌面端一套布局。
- H5 一套紧凑布局。
- 表单实例数据统一存储。
- 待办字段按业务类型和场景配置。

核心原因：

- 资产、CIP、流程审批字段必须同源，否则后续字段口径会分裂。
- H5 只是承载入口，适合做审批、确认、拍照、附件、简单填写，不适合作为独立产品线。
- 若未来出现复杂移动采集，再扩展 H5 专用组件，不拆第二套业务表单。

## 7. 工作交接方案

工作交接放在 `系统配置 > 组织权限 > 工作交接`，不是业务态待办。

覆盖范围：

- 待办转交。
- 已发起流程责任人调整。
- 资产责任人调整。
- 项目负责人调整。
- 管理员角色和数据权限移交。
- 离职、调岗、临时代理。

建议数据模型：

```text
HandoverTask
  fromUserId
  toUserId
  handoverType
  scopeJson
  status
  reason
  effectiveAt
  createdBy
  approvedBy

HandoverItem
  handoverId
  objectType
  objectId
  beforeOwnerId
  afterOwnerId
  status
  resultMessage
```

规则：

- 交接必须有审计记录。
- 涉及审批节点的自动跳过或改派必须可追溯。
- 离职场景下，流程可跳过转出人环节，但必须由规则驱动，不允许前端临时绕过。

## 8. 通用外部系统集成方案

MES 只是当前主要数据源，后续还会对接其他系统。因此系统配置中不应做成 `MES 接入配置`、`ERP/EHR 配置`、`PO/合同同步规则` 这些固定页面，而应做通用配置能力。

### 8.2 同步规则原则

- 业务侧看同步状态，不配置底层接口。
- 系统配置侧维护外部系统、接口、映射、同步规则。
- 失败任务进入 `数据接入 > 异常队列`。
- 所有同步任务进入 `数据接入 > 接入日志`。
- 合同/PO 金额变更应在审批通过后触发同步，不允许已核销后无痕修改。
- 资产转移、清退、报废、赔偿流程结束后推 ERP。
- 便携机转个人、资产赔偿财务环节结束后推 EHR。

首期做：

- 工程项目台账。
- 费用归集。
- 部分转固。
- 完全转固。
- 费用化处理。
- 完工验收。
- 生成资产卡片或待建资产池记录。
- ERP 同步状态模拟。

首期不做：

- 复杂成本分摊模型。
- 多币种、多会计准则。
- 深度施工项目管理。
- 全量 IoT/MES 运行数据治理。

## 10. 资产新增与编号闭环

资产新增不直接进入正式台账。

来源：

- ERP/PO/核销后进入待建资产池。
- 内部要货进入待建资产池。
- 手工新增进入待建资产池。
- CIP 转固资料完整时可直接生成资产卡片；资料不完整时进入待建资产池。

规则：

- 管理员批量补资产类别、数量、供应商、发票、启用日期等字段。
- 数量字段可合并展示，生成资产时按数量拆成多行资产。
- 编号规则建议为 `资产小类 + 年月 + 公共月序列`。
- “公共月序列”需最终确认是全资产共用，还是同一小类内共用。

## 11. 盘点、标签与运维策略

不建议全量强制盘点。建议采用：

- 资产分类规则。
- 抽盘策略。
- 高价值资产重点盘点。
- 数量大资产抽盘。
- 重要设备重点盘点。
- 无 MES/MAC 绑定资产重点盘点。
- 已由 MES/MAC 绑定且可证明状态的设备，可免盘或低频盘。

重点设备接入：

- 只对高价值设备做数据接入和利用率展示。
- 不把温度等传感器字段泛化到所有资产。
- 服务器、笔记本等可通过扩展字段维护专属属性。

## 12. 报表与大屏策略

报表不放顶部导航。

```text
工作概览
  常用报表
  资产态势大屏
```

规则：

- 常用报表承接跨业务、收藏、订阅、导出的入口。
- 业务级报表放在对应业务模块工具区。
- 大屏态势放在 `工作概览 > 资产态势大屏`，作为全屏展示入口。
- 页面内 KPI 只作为状态摘要，不作为一级导航。

## 13. 视觉资产与 Stitch 复刻策略

Workbench 是业务工作台，普通列表、详情、审批、配置页不强制使用图片。页面仍以表格、筛选、详情抽屉、状态摘要为主。

如果页面确实需要产品图、设备图、业务场景图、态势大屏主视觉或空状态视觉，采用以下路径：

```text
业务页面判断需要视觉资产
  -> 使用 image / image 2 生成产品图或业务图
  -> 用 Stitch 复刻为页面级设计稿或关键组件稿
  -> 对齐现有设计系统和 Workbench IA
  -> 再落到真实前端页面
  -> 用浏览器截图验证视觉、交互和响应式效果
```

适用场景：

- `工作概览 > 资产态势大屏` 需要全屏态势主视觉。
- `数据监控中心` 需要展示设备、数据链路或同步状态的可视化图。
- `资产运维中心` 需要重点设备、服务器、笔记本等产品图辅助识别。
- 空状态、首次引导、异常状态需要更清楚的业务视觉表达。
- 用户明确要求某个页面按产品图或截图复刻。

不适用场景：

- 普通资产台账、CIP 明细、审批待办、系统配置列表。
- 仅为装饰而加入图片。
- 抽象渐变、装饰插画、无业务含义的背景图。
- 用图片替代表格、状态、按钮和真实业务数据。

落地要求：

- 生成的产品图必须贴近固定资产管理场景，避免泛化 stock 风格。
- Stitch 复刻只作为设计和布局参考，最终前端仍要遵循现有组件体系。
- 生成资产需放在可管理目录，并记录用途、生成提示词摘要和页面归属。
- 涉及真实品牌、真实设备外观或客户专有场景时，需人工确认后再进入实现。
- 使用视觉资产的页面，必须额外做桌面和窄屏截图验证。

## 14. 一期实施顺序

### 阶段 1：导航和 Workbench 骨架

- 固化顶部 4 个业务视角 + 系统配置。
- 固化业务态左侧导航。
- 固化系统配置左侧导航。
- 将页面交互改为表格主导。
- 保留摘要卡，但剔除报表 KPI 主导结构。
- 如页面需要产品图或强视觉资产，按第 13 章执行 image -> Stitch -> 前端落地。

### 阶段 2：资产新增闭环

- 待建资产池。
- 资产编号。
- 资产台账入账。
- 分类与标签。
- 基础审批流程。

### 阶段 3：CIP 在建工程

- 工程项目。
- 费用归集。
- 转固管理。
- 完工验收。
- 与资产卡片和待建资产池衔接。

### 阶段 4：流程、表单、待办字段

- 流程定义。
- 流程设计器。
- 表单配置。
- 表单存储。
- 待办字段配置。
- 工作交接。

### 阶段 5：通用集成与通知

- 外部系统配置。
- 接口配置。
- 字段映射。
- 同步规则。
- Webhook 配置。
- 邮件网关配置。
- 通知模板、渠道、偏好、流程通知开关。

## 15. 验收口径

| 验收项 | 标准 |
|---|---|
| 顶部导航 | 前四个是业务视角，不切左侧导航；系统配置切后台导航。 |
| 业务左侧导航 | 与本文件第 4 章一致，无非生产物料分组。 |
| 系统配置左侧导航 | 与本文件第 5 章一致，无管理首页、配置待办。 |
| 常用报表 | 位于 `工作概览 > 常用报表`。 |
| 大屏态势 | 位于 `工作概览 > 资产态势大屏`。 |
| CIP | 作为独立业务域位于 `在建工程`。 |
| 表单 | 一套字段定义，支持桌面和 H5 布局。 |
| H5 | 挂钉钉，不建设独立移动 App。 |
| 集成配置 | 使用通用外部系统配置，不为 MES/ERP/EHR/PO/合同分别做固定配置页。 |
| 邮件 | 有邮件网关配置、流程邮件配置、邮件模板、邮件日志。 |
| 待办 | 支持按业务配置待办显示字段。 |
| 工作交接 | 支持离职、调岗、代理、资产责任人和流程待办交接。 |
| 视觉资产 | 如页面需要产品图，按 image / image 2 生成，再用 Stitch 复刻设计，最后落到真实前端并截图验证。 |

## 16. 待确认事项

| 事项 | 建议默认 | 需要确认 |
|---|---|---|
| 资产编号公共序列 | 先按同一资产小类内月序列实现 | 是否改成全资产共用月序列 |
| H5 能力边界 | 首期只做审批、确认、附件、拍照和简单填写 | 是否有复杂移动采集场景 |
| CIP 与 ERP | 首期模拟同步状态和日志 | ERP 真实接口字段和触发节点 |
| MES 接入字段 | 首期只接设备状态、绑定关系、利用率类字段 | 是否有温度等传感器字段刚需 |
| 邮件网关 | SMTP/企业邮箱优先 | 是否还需要企业微信、短信等渠道 |
| 产品图范围 | 默认只在态势大屏、空状态、重点设备识别等场景使用 | 是否有指定产品图或参考图 |
