## Borrow / Adapt / Reject 门禁

| 结论 | 绑定来源 | 门禁内容 | 对后续产品实现的约束 |
|---|---|---|---|
| Borrow | 泛微 e-workflow、泛微 e-cology、飞书审批资源概述、飞书管理员设计审批流程 | 借鉴成熟产品把流程定义拆成表单、节点、条件、处理人、字段权限、发布版本、运行轨迹。 | 流程定义页必须能承载定义列表与详情；流程详情字段必须完整展示定义元数据、节点、条件、权限和发布状态。 |
| Borrow | 泛微 e-workflow、泛微 e-cology | 借鉴图形化建模、图形化跟踪、仿真/预览、版本控制的产品门禁。 | 设计器必须有可理解的节点画布；运行态流程图必须显示当前节点、已走路由、即将路由或可解释的下一步。 |
| Borrow | 飞书审批资源概述、飞书管理员设计审批流程 | 借鉴固定开始/结束节点、人工/自动同意/自动拒绝、多审批方式、条件分支、字段权限。 | 处理人预览必须解释节点审批人来源、空审批人降级策略、或签/会签/依次审批差异。 |
| Adapt | 泛微 e-workflow、飞书管理员设计审批流程 | 将“类 Excel 表单设计”和“完整审批测试信息预览”改造为 forthAMS 的资产/工单场景表单与预览，不照搬通用 OA 后台。 | 表单和设计器必须围绕资产管理业务字段，预览应覆盖真实业务字段、处理人和条件分支。 |
| Adapt | 泛微 e-cology、飞书审批资源概述 | 将轨迹、节点字段权限、审批定义编码映射为 forthAMS 可审计的数据模型和页面字段。 | 审计轨迹必须至少覆盖操作者、动作、时间、意见；定义标识、版本、状态、适用业务必须可追踪。 |
| Borrow | 钉钉工作流概述、钉钉审批配置、阿里云 SASE 集成钉钉审批实践 | 借鉴审批配置结构、连接流治理、表单/流程/审批人面板、字段映射、事件订阅和状态回读的产品线索。 | 后续产品门禁可参考这些线索设计配置、发布、运行回读与审计边界，但必须保留证据层级限制。 |
| Adapt | 钉钉工作流概述、钉钉审批配置、阿里云 SASE 集成钉钉审批实践 | 将审批配置、连接流和 SASE 集成场景线索适配到 forthAMS 的子表单绑定、处理人预览、发布门禁、运行态回读。 | 只作为资产/工单流程平台的设计线索，不照搬钉钉 OA 后台或阿里云 SASE 安全场景。 |
| Reject | 钉钉工作流概述、钉钉审批配置、阿里云 SASE 集成钉钉审批实践 | 拒绝把阿里云 SASE 案例外推为钉钉原生全量能力或 forthAMS 已实现能力。 | 文档、规格、验收和实现不得把场景补强证据当成通用产品能力证明或完成证明。 |
| Reject | 全部来源 | 拒绝声明 P1、总体目标或功能落地状态已经完成。 | 本文只作为门禁证据；实现状态必须由后续代码、页面和测试证据另行证明。 |

## 后续产品实现约束

| 区域 | 约束 |
|---|---|
| 流程定义页 | 卡片必须位于搜索区上方；详情信息完整；分页补齐；不得因重构影响 `/dashboard`。 |
| 流程详情字段 | 必须覆盖定义标识、名称、业务类型、状态、版本、节点、条件、字段权限、处理人策略、发布信息、最近运行情况。 |
| 设计器 | 必须支持节点、条件、处理人、字段权限、开始/结束节点的可视化配置；允许按门禁结论重构流程平台页面。 |
| 运行态流程图 | 必须展示当前节点、历史流转、已走路由、可解释的下一步或结束态。 |
| 处理人预览 | 必须展示处理人来源、多人审批方式、空审批人降级策略、自动同意/自动拒绝等可执行结果。 |
| 审计轨迹 | 必须覆盖操作者、动作、时间、意见，并保留可回溯的流程版本和节点上下文。 |
| 版本发布 | 必须区分草稿、已发布、停用/回滚或等价状态；删除或停用类操作必须有明确风险提示和不可恢复边界。 |
