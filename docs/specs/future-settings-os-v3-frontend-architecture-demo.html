阶段化落地路线

先治理协议，再做框架 POC
P0 协议冻结

冻结资源、权限、安全、URL、数据、Inspector、测试合同。

P1 44 项 Registry

覆盖六域 menu、route、component、fallback、domain 与状态。

P2 权限与安全

补 route/menu/button/API、tenantScope、sensitiveFields、dangerOps。

P3 URL 与数据

规范 search params、Query key、失效策略、错误与审计反馈。

P4 六域迁移

按域迁移真实页面；流程平台按门户、设计、表单、监控分层。

P5 架构 POC

隔离验证 TanStack Start；必要时验证 Next.js 绿地壳。

风险提示

主推方案仍需治理，不能退化为继续硬编码

Registry 缺口

如果不补 44 项资源 registry 与权限元数据，V3 会继续停留在局部硬编码菜单。

安全与敏感字段

邮件网关、Webhook、文件存储、缓存、诊断包等必须有掩码、二次确认、审计和脱敏导出。

TanStack Start RC

长期方向不等于立即迁移；需等待 1.0、版本锁定与隔离 POC 证据。

Next.js 绿地反超

若未来强依赖 SSR/RSC/BFF 或 Vercel 型平台化部署，需要重新评估 Next.js。

微前端过早

团队边界未稳定前引入微前端会放大路由、权限、主题、依赖与测试治理成本。

流程平台复杂度

流程平台不能按普通 CRUD 处理，需单独分门户、设计中心、表单中心、运行监控和 Case/Record。
