为固定资产管理系统的“系统运营中枢 / 基础资料 / 编号规则”生成一个高保真桌面后台页面。请复刻 IMAGE2 产品图 `master-data-subpage-02-numbering-rules-v2.png` 的信息结构和操作密度。

目标：复刻产品图的信息结构，突出资产编号规则的试算、冲突检测和发布门禁。不要做营销页，不要做 KPI 大屏。

布局要求：
- 顶部必须是系统运营中枢壳层：顶部导航高亮“系统运营中枢”，左侧系统设置导航中“基础资料”展开，“编号规则”高亮；顶部和左侧导航都不要搜索框。
- 顶部是紧凑标题和操作按钮：新建编号规则、试算编号、冲突检测、保存草稿、提交校验。
- 操作区下方有反馈条，展示“当前草稿已保存 / 试算样本 3 条 / 冲突检测 1 项待处理”。
- 左侧是编号规则列表：小类+年月+公共月序列、CIP转固编号、IT设备编号、备件编码、临时资产编号、服务器编号、笔记本编号，显示启用/草稿状态和影响对象数量。
- 中间主区域顶部有页面内搜索框和筛选按钮：规则名称、业务对象、序列口径、状态、影响范围。
- 主表格列：规则名称、规则编码、业务对象、编号模式、序列口径、数量拆行、占号策略、状态、操作。
- 表格下方是编号试算预览：待建资产池/CIP转固输入样本、数量拆行结果、生成编号、序号、预览不占号说明。
- 下方必须有冲突检测队列：历史锁号重复、手工改号冲突、资产小类缺失、已核销批次只读，带严重级别和处理动作。
- 右侧是“编号规则属性编辑区”，字段包括：规则名称、规则编码、业务对象、编号模式、序列口径、年月格式、序列位数、数量拆行、预览是否占号、生成占号策略、冲突处理、回滚方案、审计策略、负责人。
- 右侧底部是发布门禁/回滚策略清单：编码唯一性、序列口径确认、数量拆行已配置、试算样本通过、冲突队列已处理、回滚方案已填写，并显示“已生成资产保留旧编号，新规则仅影响发布后批次”的橙色警示。

视觉要求：
- 现代中文 B2B 后台，白色面板、细分割线、克制蓝色、绿色、青色、橙色状态。
- 主体必须是规则列表、表格、编号试算和右侧表单，不能退化成通用卡片页。
- 按钮和卡片圆角不超过 8px，不要装饰球，不要暗色大屏风格。
- 搜索能力只允许出现在页面内筛选区，不允许放在顶部导航或左侧导航。
- 输出 16:10 桌面画面，适合 Vite React 实现。

## 硬性复刻要求
- 顶部业务视角和左侧导航不得放搜索框；搜索/筛选只能出现在当前专属页面内容区。
- 页面必须包含可真人模拟的保存草稿动作，并在操作反馈区显示保存结果。
- 页面必须包含可真人模拟的提交校验/发布复核动作，并在操作反馈区显示校验或复核结果。
- 新建、编辑、搜索、详情预览、保存、提交必须围绕当前业务对象完成，不得复用通用占位模板。
